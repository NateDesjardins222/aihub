# P0.1 — is the 1-minute timeline correct?

The brief: *"Atlas showed dramatically fewer candles and materially different
price structure. Treat the entire Atlas market-data/OHLC pipeline as UNPROVEN
until you establish exactly what is happening."*

This is what was established. The tool that establishes it is
`tools/candle-audit.mjs`, and it can be re-run at any time:

```
node tools/candle-audit.mjs NQ 15:30 20
node tools/candle-audit.mjs GC 03:30 30
```

It fetches the vendor payload **directly**, asks Atlas for the same window
through its own API, and reports every minute side by side. Nothing in it goes
through Atlas's code except the API under audit, so a disagreement between the
two columns is a real disagreement.

## The answer: the bars are correct

Measured 2026-09-18, live delayed feed, `limit=2000`:

| | NQ | ES | GC | CL |
| --- | --- | --- | --- | --- |
| minutes in both | 1321 | 1321 | 1329 | 1292 |
| the vendor has, Atlas lacks | 0 | 0 | 1 | 0 |
| Atlas has, the vendor lacks | 0 | 0 | 0 | 0 |
| **closed bars differing by >= half a tick** | **0** | **0** | **0** | **0** |
| bars violating `low <= open/close <= high` | 0 | 0 | 0 | 0 |
| duplicate timestamps | 0 | 0 | 0 | 0 |
| out-of-order timestamps | 0 | 0 | 0 | 0 |
| timestamps off the 1-minute grid | 0 | 0 | 0 | 0 |

The GC "vendor has, Atlas lacks: 1" is the minute that closed between the two
fetches. The one >half-tick difference in each column is the **forming** bar,
which is still moving; see the defect at the end.

Three things were checked beyond a row-by-row comparison.

**The vendor's own data is self-consistent.** Folding the vendor's 1-minute rows
into 5-minute buckets and comparing against the vendor's own 5-minute series:
265 buckets, **0 differences in open, high or low**, one difference in close -
the bucket that was still forming. So the 1-minute series is not a thinned or
resampled version of something coarser.

**The contract is the right one.** `NQ=F` and `NQZ26.CME` both return 29713.50;
`NQU26.CME` returns 29410. Atlas labels the series NQZ26 and the vendor is
serving Z26, 303 points away from the expiring September contract. No rollover
or continuous-contract contamination.

**Atlas is more accurate than the payload it is built from.** Yahoo serves gold
and crude as 32-bit floats: 4388.30 arrives as `4388.2998046875`. Atlas snaps
every price to the instrument's tick, which recovers 4388.30 exactly. 1325 of
1329 GC bars are "different" from the vendor at full float precision and
identical at tick resolution, and the tick is the resolution the market has.
The audit reports these separately rather than as differences, because calling
them differences would be calling the fix a fault.

## So why did the two charts disagree?

Not the bars. Two things, both measurable, and both about presentation.

### 1. The clock. Atlas labels the axis in exchange time; the reference did not.

CME equity index futures are an exchange-Chicago product and Atlas labels its
axis in America/Chicago. The vendor itself declares the series' exchange
timezone as `America/New_York`, and that is the convention retail futures
platforms display. **Atlas's "3:30" is a reference platform's "4:30".** Every
symptom in the brief follows from that one hour: different opens, different
closes, different highs and lows, different sequence, different timing,
different price action - the same market, an hour apart.

And it explains "dramatically fewer candles" exactly. Starting a 1-minute chart
at **15:30 Chicago** puts the left edge immediately after the 15:15-15:30
equity-index halt and 30 minutes before the 16:00-17:00 maintenance break:

```
hour (CT)   minutes the vendor has   minutes that are null
15:00-16:00            45                     15   (equity index halt)
16:00-17:00             0                     60   (daily maintenance)
```

**Sixty absent minutes inside the first ninety.** A reference chart starting at
15:30 New York (= 14:30 Chicago) shows 45 unbroken minutes of the cash session
before the halt. Same data, same instrument, half as many candles on one of
them, purely because of where the hour boundary fell.

Every one of those 60 null minutes is the maintenance break. Atlas draws a gap
there, which is what a gap is.

### 2. The feed is 602 seconds behind the exchange. Measured, not assumed.

At the same wall-clock instant, Atlas's newest candle is **ten minutes older**
than a live platform's. Comparing "the last hour" on both compares two windows
offset by ten minutes, and the right-hand edge of Atlas is missing the ten most
recent candles the reference has. That is a property of the development feed,
not of Atlas, and it is the single biggest reason the two charts cannot be read
against each other at the same clock time.

## Provider limitations, stated explicitly

The brief asked for these to be named rather than hidden.

| Limitation | Measured | Consequence |
| --- | --- | --- |
| **602-second delay** | `delaySeconds: 602`, consistently | Atlas can never be compared to a live platform at the same instant |
| **OHLCV only** | no bid, no ask, no prints, no book | no DOM, no spread, no trade-by-trade tape; fills are modelled from bars |
| **1-minute is the finest granularity** | vendor serves 1m, 5m, 15m, 30m, 1h, 1d | sub-minute timeframes cannot be built from this feed at all |
| **7 days of 1-minute history** | vendor limit | a 1-minute chart cannot scroll back further |
| **32-bit float prices on some series** | GC, CL | corrected by tick-snapping; would be a real error without it |
| **One price per poll, not a tick stream** | see P0.2 | the forming candle advances in steps, not continuously |

**This feed cannot support professional futures charting.** It is adequate to
prove the pipeline correct - which it now has - and it is not adequate for a
trader. What it cannot do is not a bug list to work through; it is a vendor
choice to reverse. See P0.2 for the latency consequence and what replacing it
requires.

## The one real defect found

**The forming bar's open can be a price that never opened that minute.**

```
22:08:00, still forming
  vendor   O 4387.50  H 4388.30  L 4385.90  C 4385.90
  Atlas    O 4388.30  H 4388.30  L 4385.90  C 4387.10
```

The high and the low agree. The open does not, by 8 ticks. Atlas builds the
current minute from the quote stream, so its open is the first price Atlas
happened to observe in that minute rather than the minute's first trade. It
self-corrects the moment the minute closes and the vendor publishes the
completed bar - which is why all 1329 closed bars reconcile - but until then the
live candle shows an open that did not happen.

Fixed: when the vendor has published a bar for the minute in progress, that bar
owns the open, and the quote stream may only extend the high, the low and the
close. Regression test: `candles.test.ts`.
